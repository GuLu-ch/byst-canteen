# 博涯小食堂 · 宝塔面板部署文档

> 适用版本：宝塔面板 8.x / 9.x（Linux 版），系统 Ubuntu 22.04 / Debian 12 / CentOS 7+
> 本文假设你要把项目部署到一台**全新的云服务器**上，用域名 + HTTPS 访问。

---

## 0. 先搞清楚：这个项目装到服务器上是「一个进程」

很多人第一反应是「前端一个站点、后端一个站点、再来个 MySQL」。**本项目不是这样**：

```
                    ┌──────────────────────────────────────────┐
   手机 / PC 浏览器 ──▶ │  Nginx（宝塔站点，监听 80/443，带 SSL）    │
                    └───────────────┬──────────────────────────┘
                                    │ 反向代理 127.0.0.1:8000
                                    ▼
                    ┌──────────────────────────────────────────┐
                    │  uvicorn  →  FastAPI（单个 Python 进程）    │
                    │  ├── /api/**   → 接口（JWT、业务逻辑）      │
                    │  └── 其它路径   → 直接吐 frontend/dist 静态文件 │
                    └───────────────┬──────────────────────────┘
                                    ▼
                            backend/data/byst.db（SQLite 单文件）
```

也就是说：

| 需要 | 不需要 |
| --- | --- |
| 1 个 **Python 项目**（uvicorn 跑 FastAPI） | ❌ MySQL / Redis（数据在 SQLite 单文件里） |
| 1 个 **Nginx 站点**做反向代理 + SSL | ❌ 单独部署前端站点（dist 由后端托管） |
| **前端先构建**出 `frontend/dist` | ❌ 服务器上常驻 Node（可在本机构建后上传） |

所以宝塔里你只需要动三个地方：**文件**（放代码）、**Python 项目**（跑后端）、**网站**（域名 + 反代 + SSL）。

## 1. 准备工作

### 1.1 服务器

- 最低 1 核 1G / 20G 硬盘；推荐 **1 核 2G**（pip 安装依赖时 1G 内存可能吃紧，可临时加 swap）。
- 系统建议 **Ubuntu 22.04 LTS** 或 **Debian 12**（宝塔对这两者兼容最好）。

### 1.2 安装宝塔面板

在服务器 SSH 里执行官方安装命令（**以宝塔官网最新命令为准**，不同系统命令不同）：

```bash
# Ubuntu / Debian
wget -O install.sh https://download.bt.cn/install/install_lts.sh && bash install.sh ed8484bec
```

安装完成后终端会打印**面板地址、用户名、密码**，请立刻保存。然后浏览器打开面板登录。

### 1.3 宝塔里要装的软件（软件商店）

| 软件 | 用途 | 说明 |
| --- | --- | --- |
| **Nginx** 1.24+ | 域名、反代、SSL | 必装 |
| **Python 项目管理器** | 跑 FastAPI | 宝塔 9.x 已内置在「网站 → Python项目」；旧版本请到「软件商店」搜「Python项目管理器」安装 |
| （可选）Node.js 版本管理器 | 在服务器构建前端 | 只在「方案 B：服务器构建」时需要 |

> 不需要安装 MySQL、PHP、Redis。

### 1.4 放行端口（**两处都要做**）

1. **云厂商安全组**：放行 `80`、`443`；（如果面板端口不是 8888，还要放行面板端口，建议加 IP 白名单）
2. **宝塔面板 → 安全**：同样放行 `80`、`443`。
3. **不要**对外放行 `8000`——它只给本机 Nginx 用。

## 2. 上传代码

目标目录：`/www/wwwroot/byst-canteen`

### 方案 A：Git 拉取（推荐，方便以后升级）

宝塔 →「终端」，或 SSH：

```bash
cd /www/wwwroot
git clone https://github.com/GuLu-ch/byst-canteen.git
cd byst-canteen
```

私有仓库用带 token 的地址：`https://<用户名>:<token>@github.com/GuLu-ch/byst-canteen.git`。

### 方案 B：上传压缩包

本地把项目打成 zip（**排除** `frontend/node_modules`、`.tmp`、`backend/.deps`、`__pycache__`），
宝塔 →「文件」→ 进入 `/www/wwwroot` → 上传 → 右键解压 → 把目录改名成 `byst-canteen`。

### 2.1 目录结构确认

上传完应该是这样（**这个相对位置不能改**，后端按它去找前端产物）：

```
/www/wwwroot/byst-canteen/
├── backend/
│   ├── app/            # FastAPI 源码
│   ├── data/           # ← 运行时生成 byst.db（要可写）
│   ├── requirements.txt
│   └── init_db.py
├── frontend/
│   └── dist/           # ← 前端构建产物（第 3 步生成），后端靠它对外提供页面
└── scripts/
```

### 2.2 目录权限

面板 →「文件」→ 右键 `byst-canteen` →「权限」：所有者选 `www`，权限 `755`，勾选「应用到子目录」。
再确保数据库目录可写：

```bash
mkdir -p /www/wwwroot/byst-canteen/backend/data
chown -R www:www /www/wwwroot/byst-canteen/backend/data
chmod 755 /www/wwwroot/byst-canteen/backend/data
```

## 3. 构建前端（二选一）

后端只认 `frontend/dist/index.html`，没有它页面会显示一段 JSON 提示（接口仍可用）。

### 方案 A：本地构建后上传（推荐，服务器不用装 Node）

在**你自己的电脑**上：

```bash
cd frontend
npm ci
npm run build
```

然后把生成的 `frontend/dist` 整个目录上传到服务器 `/www/wwwroot/byst-canteen/frontend/dist`（宝塔文件管理器直接拖）。

### 方案 B：在服务器上构建

宝塔 →「软件商店」→ 安装「Node.js 版本管理器」→ 装 Node 20；
宝塔 →「网站」→「Node 项目」里不需要建项目，直接在「终端」里：

```bash
cd /www/wwwroot/byst-canteen/frontend
npm config set registry https://registry.npmmirror.com
npm ci
npm run build
```

### 3.1 验证

```bash
ls /www/wwwroot/byst-canteen/frontend/dist
# 应看到 index.html  assets/  favicon 等
```

## 4. 安装 Python 依赖

### 4.1 装 Python 3.11（宝塔里点）

面板 →「网站」→「Python项目」→ 「环境管理」→ 安装 **3.11**（3.10～3.13 都行，**别用 3.9 及以下**，代码用了 `X | None` 类型标注）。

装好后它的路径形如 `/www/server/pyporject_evn/versions/3.11.18/bin/python`（**注意宝塔这个目录名就把 project 拼错成了 `pyporject`，是正常的**）。

### 4.2 必须给项目建独立虚拟环境（否则一定报 `ModuleNotFoundError`）

⚠️ 宝塔「Python项目」默认拿**基础 Python 环境**去跑你的代码，而基础环境里只有面板自己装的 uvicorn，
**不会有 sqlalchemy / fastapi / openpyxl** → 启动就会报：

```
ModuleNotFoundError: No module named 'sqlalchemy'
```

两个办法，任选其一：

**办法 A（推荐）：项目独立 venv**

宝塔 →「终端」：

```bash
cd /www/wwwroot/byts                 # 换成你的项目根目录
/www/server/pyporject_evn/versions/3.11.18/bin/python -m venv venv
source venv/bin/activate
pip install -U pip -i https://pypi.tuna.tsinghua.edu.cn/simple
pip install -r backend/requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
python scripts/check_env.py          # 自检：依赖 / 前端产物 / 数据库权限一次看清
```

`check_env.py` 会打印**当前 Python 解释器路径**和每个依赖的版本，正好用来确认「依赖装进了哪个 Python」：

```
Python: 3.11.18  (/www/wwwroot/byts/venv/bin/python)   ← 必须是 venv 的，不是面板基础环境
  ✓ fastapi           0.115.x
  ✓ SQLAlchemy        2.0.x
  ...
```

然后把「Python项目」的**启动命令**改成用这个 venv 的 python（绝对路径）：

```
/www/wwwroot/byts/venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --proxy-headers --forwarded-allow-ips=127.0.0.1
```

**办法 B：装进面板的基础环境**

「Python项目」→「环境管理」→ 找到 3.11.18 →「安装模块」，或命令行：

```bash
/www/server/pyporject_evn/versions/3.11.18/bin/pip install -r /www/wwwroot/byts/backend/requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

这样 `python -m uvicorn ...` 就能直接跑。缺点：污染共用环境，以后别的项目装不同版本会打架 —— 所以还是推荐 A。

> 依赖只有 7 个（fastapi / uvicorn / python-multipart / SQLAlchemy / PyJWT / openpyxl / pydantic，另加可选 tzdata），装起来很快。
> 验证是否装到了**正确**的环境里：`/www/wwwroot/byts/venv/bin/pip list | grep -i sqlalchemy`
> 本地跑自测脚本（`scripts/smoke_test.py`）才需要额外的 `httpx`：`pip install -r backend/requirements-dev.txt`，生产环境不用装。

## 5. 首次启动与数据库

### 5.1 数据库是「自动创建」的

第一次启动时后端会自动建表，并写入**一套演示数据**（12 个员工、菜单、预约、评价、反馈、投票），方便你立刻看到效果。

- 数据库文件：`backend/data/byst.db`（单文件，备份就是复制它）
- 想指定别的位置：环境变量 `BYST_DB=/www/data/byst.db`

### 5.2 正式上线：清空演示数据

演示数据只用于体验。正式用之前，在服务器上执行（**先停项目**）：

```bash
cd /www/wwwroot/byst-canteen
source venv/bin/activate
python scripts/clear_demo.py          # 预演：只打印将清空多少条
python scripts/clear_demo.py --yes    # 真正执行
```

它会清空菜单/预约/评价/反馈/投票和 12 个演示员工，**保留**管理员 `admin`、厨师 `chef`/`chef2`、系统设置、菜品标签。

> 想彻底重来（连表结构一起重建）：
> `cd backend && python init_db.py --reset`（注意：会重新灌演示数据）

## 6. 在宝塔里创建「Python 项目」

面板 →「网站」→「Python项目」→「添加Python项目」，按下表填（字段名就是面板上看到的那些）：

| 面板字段 | 填写值 |
| --- | --- |
| 项目名称 | `backend`（随意，建议和目录同名） |
| 项目路径 | `/www/wwwroot/byts/backend`（**注意是 backend 子目录**，不是仓库根） |
| Python环境 | 选第 4 步建的虚拟环境 `venv`；列表里没有就留空，靠启动命令里的绝对路径 |
| 启动方式 | **自定义**（面板若强制选，选 `uvicorn` 也行） |
| 启动命令 | `/www/wwwroot/byts/venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --proxy-headers --forwarded-allow-ips=127.0.0.1` |
| 环境变量 | `BYST_SECRET=<一串随机字符，务必改>`；可选 `BYST_TOKEN_DAYS=7` |
| 启动用户 | `www`（**别留空**，留空可能以 root 跑，之后数据文件属主会变成 root） |
| 开机启动 | ✅ 勾选 |

几个要点：

- **启动命令里用绝对路径的 venv python**，别只写 `python` / `uvicorn`——面板默认用基础环境跑，基础环境里没有 sqlalchemy（就是 `ModuleNotFoundError: No module named 'sqlalchemy'` 的原因）。
- **`--host` 用 `127.0.0.1`，不要用 `0.0.0.0`**：`0.0.0.0` 会把 8000 直接暴露到公网、绕过 Nginx 和 SSL；只监听本机由 Nginx 反代更安全。
- `--proxy-headers --forwarded-allow-ips=127.0.0.1` 让后端能拿到真实访问 IP / 协议（Nginx 在本机）。
- **不要开多个 worker**：SQLite 单写入，多进程容易 `database is locked`。要扩容请先换 MySQL/PostgreSQL。
- 「项目路径」选 `backend` 而不是仓库根：这样 `app.main:app` 才 import 得到；前端产物仍从 `../frontend/dist` 读取，不受影响。
- 添加完点「启动」，然后点「项目日志」应该能看到 `Uvicorn running on http://127.0.0.1:8000` + `Application startup complete`。

### 6.1 立刻自测（在服务器上）

```bash
curl http://127.0.0.1:8000/api/health
# {"status":"ok","service":"博涯小食堂"}
```

有这一行，说明后端活了；没有就去看项目日志。

## 7. 域名 + 反向代理 + HTTPS

### 7.1 解析域名

在域名商处把 `canteen.example.com` 的 A 记录指向服务器公网 IP。

### 7.2 让 Nginx 把请求转给 8000 端口（两种方式）

**方式一：用 Python 项目的「映射」（最省事）**

「Python项目」→ 点项目名 →「域名管理」→ 添加域名 → 打开「映射」开关，面板会自动生成一条反向代理。
然后在「网站」里给这个域名申请 SSL（见 7.3）。

**方式二：静态站点 + 只反代 `/api`（推荐，最省服务器、静态文件走 Nginx 缓存）**

站点根目录直接指向 `frontend/dist`，只把 `/api` 转给后端。**就地改配置文件**（宝塔「网站 → 站点 → 配置文件」），
在 `#CERT-APPLY-CHECK--END` 之后、`# 禁止访问的敏感文件` 之前插入这一段：

```nginx
    # ===== 博涯小食堂：SPA 静态文件 + /api 反代 =====
    client_max_body_size 20m;          # 菜单/员工 Excel 导入

    # 前端单页应用：找不到同名文件就回 index.html
    # （否则直接刷新 /admin、/menu 会 404）
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 接口转给后端。用 ^~ 是为了让这条优先于宝塔自带的 js/css、敏感文件正则
    location ^~ /api/ {
        proxy_pass http://127.0.0.1:8008;      # ← 换成你后端实际端口
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
        proxy_send_timeout 120s;
    }

    # 需要在线接口文档才打开（不需要就保持注释，等于屏蔽）
    # location ~ ^/(docs|redoc|openapi.json) {
    #     proxy_pass http://127.0.0.1:8008;
    #     proxy_set_header Host $host;
    # }
```

优点：静态资源由 Nginx 直接发（带 `expires` 缓存、不经过 Python），接口才走后端。

> ⚠️ 不要用宝塔「反向代理」面板加这一条 —— 它只会生成 `location /`，把静态文件也一起转给后端。

**方式三：全部反代给后端**

不建站点根目录，只写一条 `location / { proxy_pass http://127.0.0.1:8008; }`，由 FastAPI 自己吐 `dist`。
配置最简单，但静态文件每次都要经过 Python，且不走 Nginx 缓存，访问量上来时不如方式二。

### 7.3 开 HTTPS

站点 →「SSL」→「Let's Encrypt」→ 勾选域名 → 申请（免费，3 个月自动续签）→ 申请成功后打开「**强制 HTTPS**」。

> 说明：管理端登录态是 `httpOnly + SameSite=Lax` 的 cookie，**必须同域名访问**（不要一会儿用 IP:8000、一会儿用域名，否则会掉登录）。HTTPS 下工作正常，无需额外改代码。
> 本文以 `8000` 为例，如果你后端跑在 `8008`，把上面所有 `127.0.0.1:8000` 换成 `127.0.0.1:8008` 即可，两处（Python 项目启动命令 + Nginx 反代）必须一致。

## 8. 安全加固（上线前必做）

| 项目 | 做法 |
| --- | --- |
| 管理员密码 | 登录 `/admin` →「员工管理」→ 找到 `admin` →「编辑」→ 填新密码 → 保存（默认 `admin/123456` 一定要改） |
| 厨师账号 | 同上，`chef` / `chef2` 默认密码也是 `123456`，不用就删掉 |
| 应用密钥 | 环境变量 `BYST_SECRET` 改成一串随机字符（默认值只适合开发）；改了之后所有旧 token 失效，需要重新登录 |
| 接口文档 | 生产环境建议关掉：站点「配置文件」里加 `location ~ ^/(docs|redoc|openapi.json) { return 404; }` |
| 面板自身 | 面板端口改成不常用的、开启「面板 SSL」、设置「授权 IP」；宝塔账号开启二次验证 |
| 数据库文件 | 不要放在网站根目录下可被直接下载的位置（本项目默认在 `backend/data`，且后端不会静态暴露它） |

## 9. 备份（强烈建议，SQLite 就一个文件）

宝塔 →「计划任务」→「添加任务」：

- 任务类型：**Shell 脚本**
- 执行周期：每天 03:00
- 脚本内容：

```bash
mkdir -p /www/backup/byst
sqlite3 /www/wwwroot/byst-canteen/backend/data/byst.db ".backup '/www/backup/byst/byst-$(date +%F).db'"
find /www/backup/byst -name "byst-*.db" -mtime +14 -delete
```

> 没装 sqlite3 命令：`apt install -y sqlite3`（CentOS 用 `yum install -y sqlite`）。
> `.backup` 是热备份，服务运行中也能安全执行；直接 `cp` 在写入时可能拷到半截文件。

**恢复**：停 Python 项目 → 把备份文件覆盖回 `backend/data/byst.db` → `chown www:www` → 启动项目。

## 11. 排错速查

| 现象 | 大概率原因 | 处理 |
| --- | --- | --- |
| **`ModuleNotFoundError: No module named 'sqlalchemy'`（或 fastapi / jwt / openpyxl）** | 依赖没装进面板正在用的那个 Python 环境 | 见 4.2：建 venv 装 `backend/requirements.txt`，启动命令改成 `/…/venv/bin/python -m uvicorn …`；验证 `/…/venv/bin/pip list \| grep -i sqlalchemy` |
| **502 Bad Gateway** | 后端没起来 / 端口不对 / 启动命令路径错 | 看「Python项目 → 项目日志」；`curl 127.0.0.1:8000/api/health` |
| 打开域名看到一段 JSON「前端尚未构建」 | `frontend/dist` 没上传或位置不对 | 确认 `/www/.../frontend/dist/index.html` 存在 |
| 页面白屏、控制台 404 一堆 js | dist 上传不完整（漏了 `assets/`） | 重新上传整个 dist 目录 |
| 页面能开但接口全 404 | 反向代理没生效 | 站点「反向代理」里确认目标是 `127.0.0.1:8000` |
| **导入 Excel 报 413** | Nginx 请求体太小 | 站点配置加 `client_max_body_size 20m;` 并重载 |
| 登录成功但刷新就掉线 | 混用了 IP:8000 和域名 两种地址 | 统一用域名访问 |
| 报 `attempt to write a readonly database` | `backend/data` 属主不是 www | `chown -R www:www backend/data` |
| 报 `database is locked` | 开了多 worker / 备份直接 cp | 单 worker 运行；备份改用 `.backup` |
| 时间差 8 小时 | 服务器时区不对 | `timedatectl set-timezone Asia/Shanghai`（代码内部固定用 Asia/Shanghai 计算业务日） |
| pip 安装卡住 | 网络 | 加 `-i https://pypi.tuna.tsinghua.edu.cn/simple` |
| 面板里启动成功但外网打不开 | 安全组没放行 80/443 | 云控制台 + 宝塔「安全」都放行 |

查看日志的三个位置：

1. 宝塔「Python项目 → 日志」——应用报错（最常看这个）
2. `/www/wwwlogs/<你的域名>.error.log`——Nginx 层错误（502、413 在这里）
3. 浏览器 F12 → Network / Console——前端问题

## 附录 A：不用「Python 项目管理器」的兜底方案

有些老版本宝塔没有 Python 项目功能，可以用 systemd 托管：

```bash
cat >/etc/systemd/system/byst.service <<'EOF'
[Unit]
Description=Boya Canteen (FastAPI)
After=network.target

[Service]
Type=simple
User=www
WorkingDirectory=/www/wwwroot/byst-canteen/backend
Environment=BYST_SECRET=改成你的随机串
ExecStart=/www/wwwroot/byst-canteen/venv/bin/python -m uvicorn app.main:app \
  --host 127.0.0.1 --port 8000 --proxy-headers --forwarded-allow-ips=127.0.0.1
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now byst
systemctl status byst
journalctl -u byst -f      # 看日志
```

Nginx 反代部分与第 7 章完全一样。

## 附录 B：Docker 方式（可选）

服务器已装 Docker 时也可以容器化：本项目无外部依赖，镜像内 `pip install -r requirements.txt` + 拷贝 `frontend/dist`，
启动命令同上，映射 `127.0.0.1:8000:8000`，SQLite 文件挂载到宿主机（否则重建容器数据就没了）。
宝塔「Docker」→「容器」→「创建容器」即可，其余（域名/SSL/备份）与本文一致。

## 附录 C：与生产环境的差距提醒

- 现在是 **SQLite + 单进程**，适合几十到几百人的食堂场景；如果并发明显上来（比如上千人同时抢预约），再考虑换 MySQL/PostgreSQL + 多 worker。
- 没有做「上传图片」功能，所以不用配对象存储。
- 没有邮件/短信，账号密码靠管理员在后台重置（默认重置为 `123456`）。
