# 博涯小食堂 · 公司食堂预约与评价系统

一个面向公司内部的食堂系统：员工在手机上预约早/中/晚三餐、看本周菜单、做匿名反馈、给菜品打分、投票选「本周最爱菜」；厨师与管理员在 PC 后台看实时人数、改菜单、导出表格、看统计。

- 用户端（WAP 移动端，适配微信公众号内打开）：`/`　底部四个 Tab：**首页 / 菜单 / 评价 / 我的**，员工手机号 + 密码登录
- 管理端（PC）：`/admin`，管理员/厨师用**账号 + 密码**在独立登录页登录，纯白简约风格（固定浅色，不受用户端深色主题影响）
- 后端：Python FastAPI + SQLAlchemy 2 + SQLite
- 前端：Vue 3 + Vite + Vant 4（移动端）/ Naive UI + ECharts（管理端，参照 Soybean Admin 的后台骨架重写），同一个工程按路由拆分
- 主题色：用户端 `#05aff0`（rgb(5,175,240)）；管理端中性灰 + `#2563eb` 单色强调
- 图标全部为自绘 SVG（用户端 `frontend/src/components/AppIcon.vue`）或 Ionicons（管理端），不依赖图标字体与外部资源
- 用户端深浅双主题：首页右上角与「我的」页均有切换按钮，跟随系统并记忆在 localStorage（`byst_theme`），刷新不闪白；管理端固定浅色

## 三、快速开始

### 方式一：一键启动（Windows）

双击项目根目录的 `start.bat`，等待终端出现 `Uvicorn running on http://127.0.0.1:8000` 后，浏览器会自动打开。

- 手机端（用户端）：<http://127.0.0.1:8000>
- 管理端：<http://127.0.0.1:8000/admin>
- 接口文档（Swagger）：<http://127.0.0.1:8000/docs>

### 方式二：手动启动

```bat
cd backend
set PYTHONPATH=%cd%\.deps
python init_db.py          :: 首次运行 / 想重置演示数据时加 --reset
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

依赖：`SQLAlchemy 2`、`PyJWT`、`openpyxl`、`python-multipart`、`fastapi`、`uvicorn`（见 `backend/requirements.txt`，本项目已把 fastapi/uvicorn 等装到 `backend/.deps`）。

### 前端开发模式

```bat
cd frontend
npm run dev      :: http://127.0.0.1:5173 ，/api 自动代理到 8000
npm run build    :: 产出 dist/，后端会自动托管
```

## 五、使用流程

**员工**：登录 → 首页看「明日三餐」与投票卡（右上角「本周菜单」可直达预约）→ 菜单 Tab 勾选早/中/晚（或「同上一日 / 同上一周」）→ 评价 Tab 给今天的饭打分（低分会追问原因）→ 我的 Tab 改资料、看预约、提意见反馈、改密码。

**厨师**：`/admin` → 菜单管理（编辑每日三餐、复制上一周）→ 预约统计（区间汇总、人员明细、导出 Excel）→ 意见反馈（匿名）→ 菜品评价（分布与低分原因）→ 最爱菜投票。

**管理员**：厨师的全部功能 + 员工管理（新增/编辑/停用/重置密码/模板下载与导入）+ 系统设置（食堂信息、就餐时间、截止时间、开放天数、功能开关）。

## 六、关键业务规则

- **预约截止**：每餐「就餐前一天 HH:MM」截止（默认早餐 20:00、午餐 19:30、晚餐 20:00），过期后按钮置灰并显示原因（「已过预约截止时间」「最多提前 N 天预约」「该日期已过」）。
- **可预约范围**：今天起 `open_days` 天（默认 7 天）。
- **预约/取消**：批量接口只做「新增或恢复」，不会删除已有预约；取消必须走单独接口，且需在截止前。
- **评价**：每天一条，可覆盖；评分 ≥「良好」时后端自动清空低分原因；选「一般/很差」必须至少勾选一项原因。
- **反馈匿名**：数据库保留 `user_id` 便于追溯滥用，但所有后台接口不返回姓名、手机号、部门等任何身份字段。
- **投票**：每人每周**可多选**（最多 10 道，同一道不可重复；提交空数组即清空本周投票），只能投本周菜单里出现过的菜；本周与下一周开放，其余时间给出关闭原因。统计口径：`total_votes` 为投票人数，`total_picks` 为票数，占比按人数计算。
- **导出**：
  - 预约：xlsx（汇总 + 明细），管理端「就餐预约 → 导出 Excel」。
  - 评价：xlsx（每日汇总 + 评分分布 + 不满意原因 + 评价明细），管理端「菜品评价 → 导出 Excel」。
- **模板导入**：
  - 菜单：「菜单管理 → 导出模板」按周生成，日期/星期按天纵向合并、餐次按餐纵向合并，**早餐 5 行、午餐 6 行、晚餐 5 行**空白格（与示例模板《菜单模板_2026-11-09.xlsx》一致），已有的菜会预填；菜多时直接在该餐里插入新行即可，导入会按上下顺序整段读入并整体替换该餐。周末自动跳过，空行/空菜名自动忽略。
  - 员工：「员工管理 → 下载模板」，列顺序为 姓名 / 手机号 / 部门 / 角色 / 账号（管理员、厨师必填）/ 初始密码，手机号已存在则更新。

## 十一、本机环境踩坑记录（开发时遇到）
1. **系统代理**：DSH 会向子进程注入 `HTTP_PROXY/HTTPS_PROXY`，代理关闭后 pip / npm / Node fetch 全部 `ECONNREFUSED 127.0.0.1:7897`。解决办法是在同一条命令里先把代理环境变量清空（`[System.Environment]::SetEnvironmentVariable($k, $null)`）。npm 还需把缓存指向工作区内：`$env:npm_config_cache="<项目>\.tmp\npm-cache"`。
2. **临时目录 ACL**：某些受限沙箱下用 `tempfile.mkdtemp()`（0o700）建的目录会断继承、之后任何进程都写不进去。`scripts/pip_install.py` 通过把 `os.mkdir` 强制改为 0o777 + 自定义 `mkdtemp` 规避。
3. **Vite 8（rolldown 内核）**：
   - 首次构建可能 `spawn EPERM`（`net use` 探测），`scripts/patch_vite.py` 已打补丁。
   - `build.rollupOptions.output.manualChunks` 只接受**函数**形式；本项目用它把 `vue` / `vue-router` 固定进 `vue-vendor` 一个 chunk——否则懒加载页面会各自打一份 vue-router，`useRoute()/useRouter()` 拿到 `undefined`，管理端整页白屏。
4. **PowerShell 读文件编码**：`Get-Content -Raw` 在本机按 ANSI 解码，不要用它改 UTF-8 源码（会把中文写成乱码），用 Python 的 `read_text/write_text(encoding="utf-8")`。
